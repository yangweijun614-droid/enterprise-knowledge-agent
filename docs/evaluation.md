# 评测说明与实测结果

## 数据与执行

仓库内置 20 条制度题和 8 条审批场景。15 条制度题标记了一条或多条可见的相关条款，5 条题在指定日期和角色下没有可引用的条款。审批测试覆盖本人单据、他人单据、缺失单号、补充单号和多个单号。所有数据都是独立编写的虚构示例。

```text
python -m enterprise_agent.evaluate
python -m enterprise_agent.evaluate --json
```

第二条命令输出每条题的角色、制度生效日期、标准答案、各检索方式的 Top 5、实际引用和审批工具结果。运行时使用临时 SQLite，完成后清理，不改写平时的演示会话。

## 指标口径

| 指标 | 算法 |
| --- | --- |
| Recall@5 | 对有标签的题逐题计算「前五命中的相关条款数 ÷ 应命中条款数」，再对 15 题取算术平均 |
| 制度答案完全匹配率 | 引用 ID 集合与标注集合一致，整条引文与原文相同，且答案或拒答分支正确 |
| 无答案拒答率 | 5 条没有可见证据的问题中，返回 `no_evidence` 的比例 |
| 引文原文一致率 | 与该角色当时可见的条款原文相同的引用数 ÷ 实际引用数 |
| 引文标注精度 | 指向标注相关条款的引用数 ÷ 实际引用数 |
| 工具调用成功率 | 实际调用且工具、预期结果与单据符合的次数 ÷ 实际调用次数。预期拒绝并正确拒绝算成功 |
| 审批场景正确率 | 全部 8 条审批场景中，分支、是否调用及结果都符合预期的比例 |

所有检索方式用相同的问题、角色、日期、条款集合和 K 值。无答案题进入拒答率和完全匹配率，Recall@5 只计算有标注条款的题。缺号追问等无调用场景计入审批场景正确率。

## 本地基线

环境为 Windows、Python 3.12。本次使用本地 BM25、TF–IDF 余弦和默认的主题重排，审批分支使用真实的 MCP stdio 子进程。

| 指标 | 实测 |
| --- | ---: |
| BM25 Recall@5 | 86.67% |
| TF–IDF 余弦 Recall@5 | 86.67% |
| 混合检索加重排 Recall@5 | 86.67% |
| 制度答案完全匹配率 | 85.00%（17/20） |
| 无答案拒答率 | 100%（5/5） |
| 引文原文一致率 | 100% |
| 引文标注精度 | 100% |
| 工具调用成功率 | 100%（6/6） |
| 审批场景正确率 | 100%（8/8） |

三种检索在这批题上的 Recall@5 一致。第 p17 题「垫了钱拖了一个月，什么时候还可以递单？」和第 p18 题「在外地公干，公司包午饭还发每日补贴吗？」在三个检索方式里都没找全依据。第 p20 题找到了历史住宿条款，但抽取式回答没有把「住北京旅馆」识别为已知主题，因此拒答。逐题数据可以区分检索漏召回与证据选择失败。

这是一套自编的小规模题集。要评估真实业务效果，需要额外准备与开发题独立的匿名样本，并复测模型、延迟、并发和权限隔离。当前表格没有 Milvus、BGE 或 Qwen 的实测数据。
